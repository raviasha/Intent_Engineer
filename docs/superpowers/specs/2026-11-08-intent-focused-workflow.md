# Intent-focused workflow

Approved scope: implement the four recommendations in the November 8 comparison analysis.

1. Default application assessment to intent versus requirements. A named full-lifecycle
   mode remains available. Excluded code/test dimensions produce neither penalties nor
   enrichment questions. Reports identify their scope; comparisons never mix scopes.
2. Clarification uses existing context, asks one consequential unresolved question at a
   time, and shows a short evidence-linked understanding summary with assumptions marked.
   Answers remain evidence/proposals until the existing authenticated approval completes.
3. Show explicit outcome/constraint coverage during the existing proposal review and in
   graph exploration. Distinguish structural links, missing coverage, disputes and deliberate
   deferrals. A link or numeric score is never proof of semantic satisfaction.
4. Provide read-only topic pages alongside graph/table views. Use the authorized graph
   snapshot and stable links to requirements, decisions, assumptions, questions and evidence.

Reuse canonical YAML, stable IDs, provenance, existing approval and alternatives validation.
Keep local-first operation and permission filtering. No new command sequence, graph database,
automatic semantic mutation, code/test matching work, or generic profile platform.

Success: scope is visible; paused dimensions do not penalize or prompt; known answers are
reused; coverage and its limitations are explicit; a user can read why a requirement exists.
